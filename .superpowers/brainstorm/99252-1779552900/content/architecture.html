Architecture — 3 approches

Comment organiser Spring Boot, Angular, la base de données et les fichiers sur le VPS

A

Monolithe Spring Boot

Angular buildé et servi en ressources statiques par Spring. Un seul JAR à déployer.

[ VPS ]
└── 🟢 spring-boot.jar (port 8080)
├── /api/** → REST controllers
└── /** → Angular dist/
└── 🐘 PostgreSQL (port 5432)

Pros

  • 1 seul artifact
  • Déploiement simple
  • C'est ce qui est déjà esquissé

Cons

  • Rebuild front = rebuild back
  • Coupling fort
  • Dev inconfortable
B ★

API REST + SPA Angular + Nginx (Recommandé)

Spring Boot = API pure. Angular buildé servi par Nginx. Reverse proxy devant les deux.

[ VPS ]
├── 🌐 Nginx (port 443/80)
├── / → Angular dist/
└── /api → Spring :8080
├── 🟢 Spring Boot (port 8080)
└── /api/** → REST
├── 🐘 PostgreSQL (port 5432)
└── 📁 /uploads/ (GPX + photos)

Pros

  • Séparation claire front/back
  • Hot reload en dev
  • Pattern standard Angular+Spring
  • HTTPS naturel via Nginx

Cons

  • 2 services à maintenir
  • Config Nginx à faire
C

Approche B + Docker Compose complet

Tout le stack orchestré avec Docker Compose. Déploiement en 1 commande sur le VPS.

docker-compose.yml
├── 🌐 nginx (reverse proxy + SSL)
├── 🟢 backend (Spring Boot)
├── 🔵 frontend (Angular + Nginx)
├── 🐘 postgres
└── 📁 volumes (GPX, photos)
$ docker-compose up -d ← déploiement complet

Pros

  • Reproductible à 100%
  • Isolé de l'OS du VPS
  • Scale si besoin
  • Même env dev/prod

Cons

  • Docker à installer
  • Setup initial plus long
Ma recommandation : B ou C. B est le bon pattern pour un projet sérieux Spring+Angular. C est la version "tout packagé Docker" qui simplifie le déploiement VPS sur le long terme. Si tu veux déployer proprement sur un VPS et ne plus y penser, C est le meilleur investissement.
