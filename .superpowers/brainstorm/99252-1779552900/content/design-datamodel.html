Design — Section 1 : Modèle de données

Structure SQL PostgreSQL — 8 tables, relations claires

📋 users
id BIGSERIAL PK
username VARCHAR(50) UNIQUE
email VARCHAR(255) UNIQUE
password_hash VARCHAR
avatar_sprite_id INTEGER
role ENUM(user,admin)
strava_token VARCHAR
coros_token VARCHAR
created_at TIMESTAMP
✉ invitations
id BIGSERIAL PK
token VARCHAR(64) UNIQUE
email VARCHAR(255)
invited_by → users.id
used_at TIMESTAMP
expires_at TIMESTAMP
⛰ adventures
id BIGSERIAL PK
user_id → users.id
title VARCHAR(255)
date DATE
content TEXT (article)
type ENUM(trail,hike,ultra,race)
difficulty INTEGER (1-5)
gpx_path VARCHAR
status ENUM(draft,published)
created_at / updated_at
📊 adventure_stats
id BIGSERIAL PK
adventure_id → adventures.id
distance_km DECIMAL
elevation_gain_m INTEGER
elevation_loss_m INTEGER
duration_minutes INTEGER
max_altitude_m INTEGER
↑ extrait auto du GPX
📸 photos
id BIGSERIAL PK
adventure_id → adventures.id
file_path VARCHAR
caption VARCHAR(255)
sort_order INTEGER (1-5)
uploaded_at TIMESTAMP
🎒 equipment_items
id BIGSERIAL PK
name VARCHAR(100)
category ENUM(shoes,vest,
  poles,hat,glasses,
  backpack,watch,other)
icon_key VARCHAR
pixel_sprite_key VARCHAR
🔗 adventure_equipment
adventure_id → adventures
equipment_id → equipment_items
PK composite (adventure, equip)
⚔ user_levels (vue calculée)
user_id → users.id
total_km DECIMAL
total_elevation_m INTEGER
adventure_count INTEGER
rpg_score INTEGER
level INTEGER
↑ score = km + D+/100×2 + n×50
Notes : Migrations gérées par Flyway. H2 en dev (profil Spring dev), PostgreSQL en prod (prod). Seed data via V2__seed_data.sql (données d'exemple Joffrey avec GR54, UTOBI, etc.). Fichiers GPX + photos stockés dans un volume Docker /uploads, chemin relatif en base.
